# personal-ai-loop

Codex / Claude Codeで得たフィードバックを、自分の環境の改善へつなげる小さな仕組みです。
公開するのは検出・振り返りの手順。会話ログや学習内容は各自のPCに残します。

```text
作業中の修正・承認 → ローカルの改善キュー → personal-retro
                                         ├─ 個人設定・プロジェクトメモリ
                                         ├─ チームへのレビュー付き提案
                                         └─ 配布機構への修正案
```

## 導入

Python 3.9以上、macOS / Linux向けです。Python標準ライブラリのみを使います。
Windows、他のAIツールへの接続は未対応です。
このリポジトリを任意の場所へcloneし、そのディレクトリで実行します。

```bash
python3 install.py --tool codex --tool claude
python3 install.py --tool codex --tool claude --apply
```

使うツールだけ指定してください。1行目は変更予定を表示するだけです。
2行目で各ツールのHook設定に必要な2つのHookを追加し、スキルをリンクします。
既存の他のHooks・設定項目は保持し、変更前の設定をローカルデータ内にバックアップします。
同名のスキルや別の導入元が存在する場合は上書きせず終了します。

再起動後、Codexは `/hooks` で追加されたHookを確認して信頼してください。
信頼状態やサンドボックスの権限はインストーラーから変更しません。
Hookにローカルデータへの書き込み権限が必要です。
利用中の環境がHooksを無効にしている場合は、その環境の管理規約に従って有効化してください。

## 普段の使い方

Stop Hookが修正・承認らしい発言を検出し、次のセッション開始時に対象プロジェクトの残件をAIへ通知します。
振り返りたいときに「personal-retroで振り返って」と依頼してください。
自動でルールやメモリを書き換えたり、外部へ送信したりはしません。

```bash
python3 ~/.local/share/personal-ai-loop/app/loop.py queue --cwd "$PWD"
```

発言の本文はキューへ複製せず、セッション・作業パス・transcriptの場所・照合用ハッシュを保存します。
`inspect <ID>` は元のtranscriptを読んで根拠を表示します。
DBには機密性のあるパスが含まれ得るため、公開対象にしないでください。

## 3つの置き場

| 場所 | 管理するもの | 公開・共有 |
|---|---|---|
| このGitリポジトリ | Pythonコード、スキル、導入手順 | publicにできる |
| `~/.local/state/personal-ai-loop/` | キュー、処理済み記録、`personal.md`、共有前の草案、設定バックアップ | 本人のPCだけ |
| チームリポジトリ | レビューで採用した共通ルール・スキル・知識 | チームへ共有 |

`personal.md` は本人が採用した短い汎用設定だけを置く任意ファイルです。
セッション開始時に最大8,000文字を読みます。プロジェクト固有の記憶はAIツール既存のメモリへ保存し、別のメモリエンジンは作りません。
自分の調整は `personal.md` に保存し、配布スキルを直接書き換えないでください。
配布スキルそのものの改善はこのリポジトリで変更し、Gitで管理します。

## 更新・削除

導入先はcloneへのリンクです。移動・削除せず維持してください。
自動更新はありません。差分を確認してから更新します。

```bash
git fetch origin
git diff HEAD..origin/main
git merge --ff-only origin/main
python3 install.py --tool codex --tool claude --apply
```

ローカルデータと配布コードは別のため、コード更新で学習内容を上書きしません。
Hooksのコマンドが変わらなくても実行コードは更新されます。更新内容の確認は必要です。

```bash
python3 install.py --tool codex --tool claude --uninstall --apply
```

登録したHooksとスキルのリンクだけを外します。学習データ、バックアップ、導入元へのリンクは残します。
誤って消さないため、ローカルデータを削除するコマンドは用意していません。

## チームと使う

新メンバーに案内するのは「このリポジトリ」と「チームの共有リポジトリ」の2つです。
チーム側はTeamAIのプロジェクトスコープで配布できます。
名前が `personal-` で始まるスキルは個人側の管理領域とし、チームから同名で配布しません。
個人のキュー・メモリからチームへ全文を自動送信せず、一般化した変更だけPRへ昇格します。

TeamAIの内蔵共有通知は、確認した版では独立した停止設定がありません。
したがって標準TeamAIとそのまま併用すると通知は重複し得ます。
制約と対応案は [TeamAIとの境界](docs/teamai.md) を参照してください。

## 既存環境からの移行

[移行手順](docs/migration.md)を参照してください。既存の会話ログ・メモリのコピーは不要です。

## 検証と制限

```bash
python3 test_loop.py
```

隔離した仮のホームで、導入・再導入・削除、他のHooks保持、旧Hookの置換、両ツールのログ形式、二重検出防止、処理済み後の追加フィードバックを検証します。
既存の日本語検出ルールを基に、英語の強い表現も少数扱います。意味解析ではないため、引用の誤検知・言い換えの検出漏れはあります。
Stop時にtranscriptを全走査します。巨大なログで10秒を超える場合はHookがタイムアウトし得ます。
ログの置換・並べ替えは再検出を起こし得ます。検出結果は確定した学習ではなく、振り返り候補です。

Codexのtranscript形式は安定したAPIではありません。互換形式と `event_msg` / `response_item` 形式を扱い、未知のレコードは読み飛ばします。
導入後は実際のセッションでも候補が記録されることを確認してください。
参考: [Codex Hooks](https://developers.openai.com/codex/hooks)、[Claude Code Hooks](https://code.claude.com/docs/en/hooks)。
